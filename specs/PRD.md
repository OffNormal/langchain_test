## 1. 产品概述

### 1.1 产品愿景

打造一款**完全通过语音驱动的智能绘图工具**，让用户无需触碰鼠标、键盘或触摸屏，仅凭自然语言即可完成从草图构思到精细绘图的完整创作流程。

### 1.2 一句话价值主张

> "像与人对话一样画画——你说，它画。"

### 1.3 目标用户

| 用户画像 | 场景描述 | 核心需求 |
|---------|---------|---------|
| **无障碍用户** | 上肢运动障碍者、ALS患者等无法使用传统输入设备的人群 | 完全替代键鼠的创作能力 |
| **教育工作者** | 在线授课时需要快速绘制示意图的教师 | 边说边画，不中断教学节奏 |
| **创意工作者** | 头脑风暴、快速原型设计的设计师和产品经理 | 思维到图形的即时转换 |
| **普通消费者** | 想画画但不会使用复杂绘图软件的 Casual User | 零学习门槛的自然交互 |
| **现场工作者** | 双手被占用（如戴手套、操作设备）的工程师/技师 | 释放双手的辅助标注 |

### 1.4 核心使用场景

1. **快速草图**：口头描述，3秒内产出示意图（如"画一个三层架构图：前端、后端、数据库"）
2. **迭代修改**：持续对话式调整（"把那个圆变大一点""把红色改成蓝色"）
3. **精确绘制**：参数化指令控制尺寸、位置、对齐（"在画布中央画一个半径200px的圆"）
4. **标注与注释**：语音添加文字标签、箭头、连接线
5. **导出分享**：语音指令导出为 PNG/SVG，发送给指定联系人

### 1.5 产品差异化

| 维度 | 传统绘图工具 | 本产品 |
|------|-------------|--------|
| 输入方式 | 鼠标+键盘 | 纯语音 |
| 学习曲线 | 陡峭（需学习工具栏、快捷键） | 平缓（自然语言即可） |
| 操作精度 | 像素级（依赖手部精细运动） | 参数化精度（语音指定数值） |
| 多任务能力 | 单线程操作 | 批量指令执行 |
| 可访问性 | 依赖健全上肢 | WCAG AAA 级可访问 |

## 3. 语音交互设计

### 3.1 指令语法设计

核心语法采用 **`[唤醒/动作] [目标对象] [参数列表]`** 结构化模式，兼顾精确控制与自然表达。

#### 3.1.1 指令层级

```
Level 1: 精确指令（结构化）
  模式: [动作] [对象类型] [参数=值, ...]
  示例: "画 圆 半径=100, 颜色=红色, 位置=中心"
  优点: 高准确率，适合复杂参数

Level 2: 自然语义（半结构化）
  模式: [自然语言描述]
  示例: "在画布中间画一个红色的圆圈，大概这么大"
  优点: 低学习门槛，适合快速输入

Level 3: 上下文对话（非结构化）
  模式: [指代 + 修改意图]
  示例: "把它变大一点" "不对，再小一些"
  优点: 自然迭代，适合精细调整
```

#### 3.1.2 指令分类

| 类别 | 动作词 | 示例 |
|------|--------|------|
| 创建 | 画、添加、新建、绘制、插入 | "画一个矩形" |
| 修改 | 改、设置、调整、变成、换 | "把颜色改成蓝色" |
| 删除 | 删除、去掉、移除、清空 | "删除这个圆" |
| 查询 | 这是什么、多大、什么颜色 | "当前颜色是什么" |
| 导航 | 放大、缩小、平移、跳转 | "放大到 200%" |
| 文件 | 保存、导出、打开、新建 | "导出为 PNG" |
| 编辑 | 复制、粘贴、剪切、撤销 | "复制这个矩形" |
| 布局 | 对齐、分布、排序、居中 | "左对齐这两个图形" |

### 3.2 核心指令词汇表

#### 3.2.1 图形对象词汇

```
基本形状: 圆形(圆), 矩形(长方形/正方形), 三角形, 直线(线), 箭头, 椭圆,
          多边形, 星形, 曲线, 弧线
组合: 组, 群组, 图层
参考: 画布, 背景, 网格, 坐标轴
```

#### 3.2.2 属性词汇

```
颜色: 红, 橙, 黄, 绿, 蓝, 紫, 黑, 白, 灰, 粉, 青, 棕, 透明
      深红, 浅蓝, 亮绿, 暗紫 (深浅变体)
      自定义: hex值, rgb值

尺寸: 宽, 高, 半径, 直径, 粗细, 大小
      像素(px), 厘米(cm), 百分比(%)

位置: 左边, 右边, 上面, 下面, 左上角, 右下角
      中心, 居中, 顶部, 底部
      偏移: 向左移50像素, 往上挪一点

样式: 实线, 虚线, 点线, 双线
      填充, 描边, 空心, 实心
      透明度, 阴影, 圆角
```

#### 3.2.3 程度/修饰词

```
大小: 大, 小, 巨大, 微小, 中等
      更大/更小, 最大/最小
      放大/缩小 + 倍数/百分比

数量: 一个, 两个, 三个...
      几个, 一些, 所有

程度: 稍微, 一点, 非常, 极其
      更..., 最...
```

### 3.3 唤醒模式设计

| 模式 | 描述 | 适用场景 | 优缺点 |
|------|------|---------|--------|
| **始终监听 (Always-On)** | 持续监听，用唤醒词触发 | 完全免提场景 | 优: 真正的免提; 缺: 功耗高，隐私顾虑 |
| **按键说话 (PTT)** | 按住空格/脚踏板说话 | 桌面端 | 优: 隐私性好，误触发率低; 缺: 需要物理接触 |
| **注视说话 (Look-to-Talk)** | 注视摄像头/屏幕时激活 | 有摄像头的设备 | 优: 自然交互; 缺: 依赖硬件 |
| **混合模式** | 默认 PTT + 可选 Always-On | 通用推荐方案 | 灵活兼顾 |

**推荐**: V1.0 采用 **空格键 PTT**（桌面端默认）+ **唤醒词 "嘿画板"**（可选开启），移动端默认 PTT 按钮。

### 3.4 反馈闭环设计

语音指令执行过程中，系统必须提供**多层反馈**以建立用户信任：

```
时间线:
  用户说话 ──[100ms]──> 语音波形可视化 ──[300ms]──> ASR文本回显
       ──[500ms]──> NLU解析结果高亮 ──[50ms]──> 画布操作预览
       ──[50ms]──> 操作完成确认 ──> 语音/音效反馈(可选)
```

| 反馈层 | 形式 | 作用 |
|--------|------|------|
| **接收确认** | 麦克风图标 + 波形动效 | 告知系统正在听 |
| **文本回显** | 屏幕字幕 / 气泡文字 | 确认听到了什么 |
| **语义解析** | 指令关键词高亮 | 展示理解结果 |
| **操作预览** | 画布上的半透明预览 | 所见即所得 |
| **完成确认** | 音效 / 语音播报 / Toast | 告知操作已完成 |

### 3.5 歧义消解策略

当系统无法确定用户意图时，按以下优先级处理：

```
策略1: 上下文推断 (置信度 >85% → 直接执行)
策略2: 最佳猜测执行 + 保留撤销入口 (置信度 60%-85%)
策略3: 主动澄清对话 (置信度 <60% 或多候选接近)
策略4: 安全回退，提示用户重述
```

**澄清对话示例**：

```
用户: "画一个圈"
系统: 置信度 65% → 画一个圆形，同时在角落提示"我画了一个圆，不对可以说'不是圆形'"
--- 分支 ---
用户: "对，就这个" → 保留
用户: "不对" → 撤销，询问 "你要画的是圆形还是椭圆形？"

用户: "把它放那边"
系统: 置信度 45% → 主动询问 "你想把它放到哪个位置？可以说'左边'、'右边'、'上面'或具体位置"
```

### 4.2 组件职责

#### 4.2.1 ASR 引擎 (Automatic Speech Recognition)

| 职责 | 说明 |
|------|------|
| 音频采集 | 浏览器 `MediaDevices.getUserMedia()` |
| VAD (Voice Activity Detection) | 检测语音起止，自动截断静音段 |
| 语音转文字 | 实时流式/离线批量转写 |

**技术选型**（全部国产）:

| 方案 | 延迟 | 中文准确率 | 成本 | 推荐 |
|------|------|-----------|------|------|
| **浏览器 Speech API** | 50-150ms | ★★★☆☆ | 免费 | MVP 快速原型 |
| **讯飞语音识别** | 100-300ms | ★★★★★ | 按量付费 | 中文场景首选 |
| **阿里云智能语音** | 100-300ms | ★★★★★ | 按量付费 | 备选方案 |
| **百度语音识别** | 100-300ms | ★★★★☆ | 按量付费 | 备选方案 |

#### 4.2.2 NLU 引擎 (Natural Language Understanding) — 基于 LangChain 编排

| 职责 | 说明 |
|------|------|
| 意图分类 | 识别操作类别：CREATE / MODIFY / DELETE / NAVIGATE / FILE / QUERY |
| 槽位填充 | 提取参数：对象类型、颜色、位置、尺寸、数量等 |
| 指代消解 | 解析"它""这个""那个"的指代对象 |
| 置信度评估 | 输出解析结果的置信度评分 |

**MVP: LangChain 直链模式**:

```
LangChain NLU Chain:
  ChatPromptTemplate
    → ChatModel (国产 LLM)
    → StructuredOutputParser (Zod Schema)
    → DrawingCommand 结构化输出
```

简单指令走规则引擎（<5ms），规则不匹配则走 LLM 解析。MVP 阶段不做复杂的意图路由分支——LLM 输出置信度低时直接提示用户重述。

**V1.0+ 引入 LangGraph**: 管理意图路由、置信度分支、复合指令拆解和澄清对话回环等有状态流程。

**国产 LLM 选型**:

| 模型 | API 服务 | 中文能力 | LangChain 集成 | 推荐 |
|------|---------|---------|---------------|------|
| **通义千问 (Qwen)** | 阿里云 DashScope | ★★★★★ | `langchain_tongyi` | 首选，社区集成好 |
| **DeepSeek-V3** | DeepSeek API | ★★★★★ | `langchain_deepseek` | 性价比极高 |
| **智谱 GLM-4** | 智谱开放平台 | ★★★★★ | `langchain_zhipu` | 多模态能力好 |
| **Moonshot (Kimi)** | Moonshot API | ★★★★☆ | 标准 OpenAI 兼容接口 | 长上下文优势 |

**LangChain 调用示例 (MVP)**:

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import JsonOutputParser
from langchain_deepseek import ChatDeepSeek  # 或 ChatTongyi / ChatZhipu

llm = ChatDeepSeek(model="deepseek-chat", temperature=0.1)
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是绘图指令解析器，将用户语音转写解析为结构化绘图指令..."),
    ("user", "{user_input}")
])
parser = JsonOutputParser(pydantic_object=DrawingCommand)
chain = prompt | llm | parser

# 调用
result = chain.invoke({"user_input": "画一个红色的圆"})
# result → { "intent": "CREATE_SHAPE", "shape": "circle", "color": "#EF4444", ... }
```

**NLU 降级链** (LangChain Fallback):

```
规则引擎 匹配? ──Yes──> 直接返回 (跳过 LLM, <5ms)
    │No
    └──> LangChain LLM Chain → 成功 → 返回
                              → 失败 → 重试 1 次 → 仍失败 → 友好提示
```

## 5. 复杂指令处理（V1.0 规划）

### 5.1 复杂指令分类

#### 5.1.1 多步串联指令

单次语音中包含多个连续操作：

```
用户: "画一个红色矩形, 然后在右边放一个蓝色圆形, 再用箭头把它们连起来"

解析为命令序列:
  1. CREATE rect { color: "red", position: {x: 100, y: 200} }
  2. CREATE circle { color: "blue", position: {x: 500, y: 200} }
  3. CREATE arrow { from: "rect_1", to: "circle_1" }
```

**处理流程**:

```
原始语音
  → ASR 转写
  → LangChain LLM Chain 分段识别
      ├── 子句1: "画一个红色矩形"
      ├── 子句2: "然后在右边放一个蓝色圆形"
      └── 子句3: "再用箭头把它们连起来"
  → 指代消解 (连接词 "然后""再" → 顺序依赖)
  → 空间推理 ("右边" → X偏移计算)
  → 批量执行
```

#### 5.1.2 空间推理指令

涉及相对位置的描述：

```
词汇映射表:

"左边/右侧"    → relativeX = -offset / +offset
"上面/下面"    → relativeY = -offset / +offset
"中间/之间"    → (A.x + B.x) / 2
"围绕/周围"    → 圆形排列布局
"对齐/排列"    → 对齐到相同 X/Y
"等距分布"     → 均匀分布在两点之间
```

**示例**:

```
用户: "在最大的那个圆的下方, 画一个和它一样大的正方形, 间距20像素"

解析:
  1. 指代消解: "最大的那个圆" → 查找画布上半径最大的圆对象
  2. 位置计算: 下方 = (圆心.x, 圆心.y + 半径 + 20 + 正方形.高/2)
  3. 属性继承: "一样大" → 正方形边长 = 圆的直径
  4. 执行: CREATE rect { x, y, width: 2*r, height: 2*r }
```

#### 5.1.3 批量操作指令

```
用户: "把所有红色图形变成蓝色"

解析:
  1. 条件过滤: color === "red" 的所有对象
  2. 批量执行: forEach obj → obj.fill = "blue"
  3. 打包为单次 Undo 单位
```

### 5.2 对话上下文管理

```
ContextWindow {
  maxTurns: 10,              // 保留最近 10 轮对话
  turns: [
    {
      userUtterance: string,
      parsedIntent: Intent,
      executedCommands: Command[],
      affectedObjectIds: string[],
    }
  ],
}
```

**上下文感知示例**:

```
轮次1: "画一个蓝色的圆"
      → 执行: CREATE circle { color: "blue", r: 100 }
      → 上下文: lastAffected = ["obj_001"]

轮次2: "把它复制到右边"  ← "它" 指代 obj_001
      → 指代消解: "它" → obj_001
      → 执行: CLONE obj_001, MOVE deltaX = +200

轮次3: "把这个也变成红色"  ← "这个也" 指代刚复制的 obj_002
      → 指代消解: "这个" → obj_002 (最后创建的对象)
      → 执行: SET fill = "red"
```

### 5.3 模糊限制与智能推断

当用户指令缺少参数时，系统使用合理的默认值：

```
"画一个圆"           → r=100, color=黑色, position=画布中心
"画一个小圆"         → r=50, color=黑色, position=画布中心
"画一个大红色的圆"   → r=200, color=红色, position=画布中心
"在这儿画个圈"       → r=80, position=最后操作位置偏移, color=当前色
```

推断优先级：
1. 用户明确指定的参数（最高优先级）
2. 上下文继承的参数（如当前颜色、上次尺寸）
3. 修饰词映射（"大"=200, "小"=50, "巨大"=400）
4. 画布自适应默认值

## 6. 性能要求

### 6.1 端到端延迟预算 (MVP 放宽)

```
           ┌─ 音频采集 ──┬─ ASR ────┬─ NLU (LLM) ─┬─ 渲染 ──┐
           │             │          │             │          │
MVP 目标:   <200ms        <800ms     <1500ms       <200ms     = <2.7s
V1.0 目标:  <100ms        <400ms    <800ms         <100ms     = <1.4s
```

| 环节 | MVP 目标 | 备注 |
|------|---------|------|
| 音频采集 + VAD | <200ms | 浏览器内置 API |
| ASR (浏览器 Speech API) | <800ms | 免费，无需额外服务 |
| NLU (LangChain → DeepSeek API) | <1500ms | LLM 网络调用是延迟大头 |
| Canvas 渲染 | <200ms | 简单图形渲染很快 |
| **端到端总计 (MVP)** | **<3s** | 用户可接受的等待感 |

> MVP 阶段不追求极致性能，优先验证语音交互闭环的可行性。延迟优化放在 V1.0。

### 6.2 MVP 阶段性能策略

- **规则优先**: 简单指令走规则引擎（<5ms），只有复杂指令才调 LLM
- **乐观渲染**: 语音识别过程中同步准备 Canvas 上下文，不等 NLU 完成先显示占位
- **单一 LLM 调用**: MVP 阶段不做复杂降级链，只保留"规则引擎 → LLM"两级

### 6.3 资源要求 (MVP)

| 指标 | MVP 目标 | 说明 |
|------|--------|------|
| 内存占用 | <500MB | 允许较高的浏览器开销 |
| 网络 | 需要联网 | LLM 依赖云服务 |
| 浏览器 | Chrome 114+ / Edge 114+ | 主要支持 Speech API 的浏览器 |

## 7. 容错与纠错

语音交互天然存在识别误差，系统的核心容错策略是**"快速执行 + 即时撤销"**，降低单次错误的代价。

### 7.1 三级容错机制

| 层面 | 策略 | 说明 |
|------|------|------|
| **ASR 层面** | 拼音白名单 + 领域词汇优先 | 同音词("园"→"圆")、近音词("宏色"→"红色")自动纠正 |
| **NLU 层面** | 置信度分层处理 | 高置信直接执行 / 低置信提示重述 |
| **LLM 故障** | LangChain Fallback → 规则引擎兜底 | LLM 超时或失败时，常见指令仍可通过规则引擎处理 |

### 7.2 用户侧纠错

用户只需说**"撤销"**即可回退任何操作，无需学习复杂纠错指令。

```
"撤销"           → 撤销最近 1 步
"撤销 3 步"     → 批量撤销
"不对"           → 快捷撤销（情绪识别）
"不是这个颜色"   → 针对性撤销（只撤销颜色修改）
```

### 7.3 异常兜底

| 异常 | 处理 |
|------|------|
| ASR 超时 / 听不清 | 提示"请再说一遍" |
| NLU 无法理解 | 回显原文 + "换个说法试试？" |
| LLM API 故障 | 降级到规则引擎 + 友好提示 |
| 浏览器不支持语音 | 提示使用 Chrome/Edge |

## 10. 风险与依赖

### 10.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| **中文 ASR 准确率不足** | 用户重复率高，体验差 | 中 | 图形/颜色领域词汇白名单；拼音容错匹配 |

### 10.2 产品风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
